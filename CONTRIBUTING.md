# Contributing to human-to-code

Thanks for helping improve human-to-code.

From a source checkout:

```bash
git clone https://github.com/sharjeelbaig/human-to-code
cd human-to-code
npm ci
npm run build
npm test
npm run typecheck
npm run package:check
```

The command users depend on is:

```bash
npx human-to-code .
```

`src/cli.ts` owns argument parsing and output. `src/workflows/` sequences
planning, generation, repair, integration reconciliation, and compiler-mode
gates. `src/tools/` owns focused discovery, compiler, validation, security, and
write capabilities. `src/memory/` owns bounded project and file context.
`src/prompts/` owns model-facing messages, and `src/llms/` owns provider
transport.

Compiler-mode requirement rules live in
`src/tools/compiler/requirement-rules.ts`. Add a word-bounded trigger and pure
facet detectors, then pin both an underspecified and fully specified request in
`test/compiler-rules.test.ts`. Detectors must cap scanned input and avoid
backtracking-prone expressions.

`PROMPT_VERSION` in `src/prompts/index.ts` is part of the compile key. Bump it
whenever a prompt change can alter generated bytes; failing to bump it can make
compiler replay return output produced by an older prompt.

Compiler mode is intentionally unit-isolated. Do not add ProjectMemory, session
history, model skills, classification, planning, or reconciliation to its
generation path; those belong to normal mode. Inline compilation may use only
the local surrounding source and FileMemory required to resolve visible
symbols.

Keep changes focused. Add a regression test for behavior changes, preserve exact
source bytes outside requested marker ranges, and keep provider calls injectable
in tests. Never add a path that executes repository code during discovery or
preview. Always add comments for what any code line or block does with example, like "This codeblock runs when we pass the init flag for example `npx human-to-code . --init`" or "This codeblock runs when we give invalid arguments like `npx human-to-code . --blahblah`". For any exception/error handling code block, explain in comments how to reproduce that error.

Before opening a pull request, run every development check shown above and make
sure `git status` contains no generated package tarballs or unrelated files.
